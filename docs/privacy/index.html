Privacy Policy — BrandOS

Last updated: 27 July 2026

Deutsche Fassung weiter unten ↓

BrandOS collects no data about you. It has no user accounts, sets no cookies, runs no analytics, and is not reachable from the internet. This page exists because API providers require a privacy policy — and because the honest answer deserves to be written down rather than assumed.

1. What BrandOS is

BrandOS is a private e-commerce market research tool. It is operated by one person, for that person's own use, on that person's own computer. It runs at localhost and is not published, not hosted, and not offered to anyone else. There is no sign-up, because there is nobody to sign up.

The source code is public at github.com/jannisgra1711/brandos. Every statement on this page can be checked against it.

This is a private, non-commercial project. There is no company behind it.

3. Data collected from visitors or users

None. Specifically, BrandOS does not:

  • offer user accounts, logins, or authentication of any kind;
  • set cookies or write to localStorage;
  • run analytics, tracking pixels, session recording, or advertising;
  • load fonts, scripts, or images from third-party servers;
  • accept connections from the internet — it binds to the local machine only.

This page itself is served as static HTML by GitHub Pages and loads no external resources. GitHub may log requests to it under its own privacy statement; that is outside the operator's control and no such data is received or used.

4. Data BrandOS stores

BrandOS stores the market analyses the operator runs: the search term entered, the market signals retrieved for it, and the resulting score. These are written as JSON files to a .data/ directory on the operator's own computer.

There is no database, no cloud storage, no backup service, and no transmission of these files anywhere. They contain market data about product categories — terms such as "enamel mug" or "bikepacking" — and no personal data about any person.

5. Third parties BrandOS contacts

To retrieve market data, BrandOS sends the operator's own search term to the following services. Nothing else is sent — no identifiers, no profile, no personal data.

ServiceWhat is sentWhy
SerpAPIthe search termGoogle Trends and eBay market data
Etsy Open API v3the search termlisting counts, prices, listing age
Pinterest APIthe search termaggregate trend and audience signals — planned, see section 6
Anthropic APIthe aggregated market signalsoptional written interpretation — currently disabled, see below

The Anthropic connection is switched off. BrandOS runs in heuristic mode and no API key is configured; the opportunity score is computed deterministically without any model involvement. Should this ever be enabled, only aggregate market signals would be sent — never personal data.

6. Pinterest data

BrandOS has applied for Pinterest API access. The integration is not built yet; this section states in advance what it will and will not do, and is binding on it.

What would be requested: aggregate, non-personal market signals only —

  • keyword and trend data for a product category;
  • audience characteristics expressed as shares of an aggregate, for example "42 % of interest in this category comes from segment X";
  • aggregate design signals: dominant colour palettes, recurring motifs, and how often each appears.

What would never be requested, stored, or processed:

  • data about identifiable Pinterest users — no names, no profiles, no user IDs;
  • individual pins, boards, or the activity of any person;
  • anything permitting a person to be singled out or re-identified.

How it would be handled: responses are cached on the operator's local disk for 12 hours and then discarded. Aggregate values that enter a stored analysis remain in that local file until the operator deletes it. Pinterest data is never shared, never sold, never combined with data from another source to build a profile, and never leaves the operator's machine. It is used for one purpose: the operator's own product research.

If the built integration ever needs more than the above, this page is updated before that code is used.

7. Retention

  • Analyses: kept until the operator deletes them. Deletion is available in the application and removes the file from disk.
  • Provider response cache: 12 hours, then discarded.
  • Visitor data: none exists, so none is retained.

8. Disclosure to others

None. No data is sold, rented, shared, or disclosed to any third party. There are no processors, no advertising partners, and no analytics vendors. The only outbound traffic is the requests listed in section 5.

9. Your rights

Under Art. 15–21 GDPR you have the right to access, rectification, erasure, restriction, data portability, and objection, and the right to lodge a complaint with a supervisory authority. Because no personal data is collected, there is in practice nothing to disclose or erase — but any such request is answered at the address in section 2.

10. Changes

Changes are published on this page with a new date. The full revision history is public in the repository.

4. Daten, die BrandOS speichert

BrandOS speichert die Analysen, die der Betreiber durchführt: den eingegebenen Suchbegriff, die dazu abgerufenen Marktsignale und den daraus berechneten Score. Sie werden als JSON-Dateien in einem Verzeichnis .data/ auf dem Rechner des Betreibers abgelegt.

Es gibt keine Datenbank, keinen Cloud-Speicher, keinen Sicherungsdienst und keine Übertragung dieser Dateien an irgendeinen Ort. Sie enthalten Marktdaten zu Produktkategorien — Begriffe wie „Emaille Tasse" oder „Bikepacking" — und keine personenbezogenen Daten.

5. Dritte, die BrandOS kontaktiert

Um Marktdaten abzurufen, sendet BrandOS den Suchbegriff des Betreibers an die folgenden Dienste. Mehr wird nicht übermittelt — keine Kennungen, kein Profil, keine personenbezogenen Daten.

Würde sie je aktiviert, gingen ausschließlich aggregierte Marktsignale hinaus — niemals personenbezogene Daten.

6. Pinterest-Daten

BrandOS hat Zugang zur Pinterest-API beantragt. Die Anbindung ist noch nicht gebaut; dieser Abschnitt legt vorab fest, was sie tun wird und was nicht, und bindet sie daran.

Was abgerufen würde: ausschließlich aggregierte, nicht personenbezogene Marktsignale —

  • Keyword- und Trenddaten zu einer Produktkategorie;
  • Zielgruppenmerkmale als Anteile an einer Gesamtheit, etwa „42 % des Interesses an dieser Kategorie entfallen auf Segment X";
  • aggregierte Gestaltungssignale: vorherrschende Farbpaletten, wiederkehrende Motive und deren Häufigkeit.

Was niemals abgerufen, gespeichert oder verarbeitet würde:

  • Daten identifizierbarer Pinterest-Nutzer — keine Namen, keine Profile, keine Nutzerkennungen;
  • einzelne Pins, Pinnwände oder das Verhalten einzelner Personen;
  • alles, was das Herausgreifen oder Wiedererkennen einer Person erlaubt.

Wie damit umgegangen würde: Antworten werden 12 Stunden lang auf der lokalen Platte des Betreibers zwischengespeichert und danach verworfen. Aggregierte Werte, die in eine gespeicherte Analyse eingehen, bleiben in dieser lokalen Datei, bis der Betreiber sie löscht. Pinterest-Daten werden nicht weitergegeben, nicht verkauft, nicht mit Daten anderer Quellen zu einem Profil verbunden und verlassen den Rechner des Betreibers nicht. Sie dienen einem einzigen Zweck: der eigenen Produktrecherche des Betreibers.

Sollte die gebaute Anbindung je mehr als das Vorstehende benötigen, wird diese Seite aktualisiert, bevor der Code zum Einsatz kommt.

7. Speicherdauer

  • Analysen: bis der Betreiber sie löscht. Das Löschen steht in der Anwendung zur Verfügung und entfernt die Datei von der Platte.
  • Antwort-Cache der Quellen: 12 Stunden, danach verworfen.
  • Besucherdaten: existieren nicht, werden folglich auch nicht aufbewahrt.

8. Weitergabe an Dritte

Findet nicht statt. Es werden keine Daten verkauft, vermietet, geteilt oder an Dritte offengelegt. Es gibt keine Auftragsverarbeiter, keine Werbepartner und keine Analyse-Dienstleister. Der einzige ausgehende Verkehr sind die in Abschnitt 5 aufgeführten Abrufe.
